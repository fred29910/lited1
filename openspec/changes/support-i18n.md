# 在 Lit 中支持 i18n

- **作者**：Gemini
- **状态**：草稿
- **创建于**：2025-10-23
- **更新于**：2025-10-23

## 摘要

本提案概述了为基于 Lit 的应用程序添加国际化 (i18n) 支持的计划。这将使应用程序能够被翻译成多种语言，从而让更广泛的受众能够访问。

## 动机

随着应用程序的增长，有必要为来自不同地区、讲不同语言的用户提供支持。添加 i18n 支持是使应用程序对全球受众更具包容性和用户友好性的关键一步。

## 提案

建议的解决方案包括以下步骤：

1.  **选择一个 i18n 库：** 我们将评估并选择一个与 Lit 集成良好的合适 i18n 库。一些潜在的候选库包括 `lit-i18n`、`@lit/localize` 或像 `i18next` 这样与框架无关的库。
2.  **创建一个本地化服务：** 将创建一个专门的服务来管理语言环境的加载和切换。
3.  **提取字符串：** 应用程序中所有面向用户的字符串都将被提取到资源文件（例如 JSON 或 XLIFF）中。
4.  **与组件集成：** i18n 库将被集成到 Lit 组件中以显示翻译后的字符串。
5.  **实现一个语言切换器：** 将添加一个 UI 组件以允许用户在支持的语言之间切换。

## 替代方案

-   **手动实现：** 我们可以实现一个自定义的 i18n 解决方案，而不使用第三方库。然而，这会更耗时，并且可能不如使用一个成熟的库那样健壮。
-   **服务器端渲染：** 我们可以在服务器端处理 i18n，但这会增加架构的复杂性，并且可能不适合客户端应用程序。

## 未解决的问题

-   哪个 i18n 库最适合我们的需求？
-   翻译资源文件的流程是什么？
-   我们将如何处理复数形式和其他复杂的 i18n 情况？
